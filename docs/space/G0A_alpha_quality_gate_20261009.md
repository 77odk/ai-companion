# Space V2 G0-A · RGBA 像素透明度与切图污染核查（2026-10-09）

**范围**：PR #233 / `fix/space-mobile-visual-baseline`，与 `G0A_asset_depth_audit_20261009.md` 互补。本批只针对美术资源做只读核查，不修改已有 public/ 图片；不触碰聊天、记忆、同步、后端、依赖；不合并或部署。

## 为什么补这道门

`scripts/test_space_scene_layer.mjs` 当前以 PNG IHDR color type=6 判断“RGBA”。**color type=6 只能证明存有 alpha 通道，不能证明素材是真正洁净独立的透明物件**。例如：外部背景可能残留在半透明像素，或者叶片、书页、桌角一起被切进别的物件中。

## 实际解压像素核查（不是读取头部推测）

使用仅用于此次核对的纯 JavaScript PNG zlib/DEFLATE 解码、PNG 行过滤还原，统计实际 RGBA alpha 值（下表是 GitHub 对应分支的二进制内容）。

| 资源 | 尺寸 | alpha=0（透明） | 0<alpha<255（半透明） | alpha=255（不透明） |
|---|---:|---:|---:|---:|
| `origami_coral.png` | 81×105 | 3,308 | 5,197 | 0 |
| `glass_memory_jar.png` | 212×305 | 15,865 | 48,795 | 0 |
| `open_book.png` | 480×223 | 29,569 | 77,471 | 0 |
| `wired_earphones.png` | 294×192 | 30,507 | 25,941 | 0 |

**已知结论**：以上四张 PNG 的确有全透明像素，因此并非纯不透明背景伪装的 RGBA；但四张图均没有 alpha=255 像素，且半透明像素占比较高。不能把这种格式事实直接当成“边缘干净/画面不会透背景”的视觉保证。

## 额外可视内容复核（不得绕过）

仓库原始独立资源外观检查出现以下风险，需要与 941×1672 定稿分层母版逐件确认：

- `open_book.png`：书主体左上还出现绿色藤叶，左下带疑似织物/邻接物件区域。独立书层移动时可能把别的物体带着移动。
- `hanging_plant.png`：叶片之外，下部右侧还出现桌角/明亮家具几何。单独挂植物动效可能把桌角一起晃动。
- `photo_wall_board.png`：木框左上及左侧包含藤蔓，可能与独立 `hanging_plant.png` 或烘焙背景植物叠影。
- `glass_memory_jar.png`：罐体右侧出现其他彩色星形碎片/邻接图案；需要确认是否真的属于罐体轮廓还是裁切污染。

**重要限定**：这是人工视图观察得到的“待核对风险”，未做定稿母版的逐像素重合检验；不能自行认定为已被修复，也不能直接从旧资源删除这些像素（public/ 原图受 A 级保护）。

## 验收要求（G0-A）

1. 以确定的 941×1672 定稿为基准，分别测量物件 alpha 边界、锚点、桌面接触线、接触阴影和遮挡层级。
2. 对必须“会动”的独立物件，检查 1px / 5px 透明边界、半透明 RGB 残留和与背景重叠，至少抽检：一张星星、玻璃罐、思绪书、耳机线、悬垂植物、照片墙、抽屉。
3. 将视觉污染和纯特效光晕区分，必要时**新增带新文件名**的修正版，不修改/覆盖仓库现有资源。
4. 底图仍是 864×1536 JPEG 重采样结果：继续保留“非原生高清”阻塞；失败的全新桌子试绘不能接入。
5. 以上条件未达到前，不将 PNG alpha 值统计/CI 绿/manifest enabled:true 误报为像素级视觉验收完成；PR 保持 Draft。
